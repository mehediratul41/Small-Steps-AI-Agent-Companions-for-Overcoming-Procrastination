# Troubleshooting

Start with the mode label, current account, backend `/health` and the installed APK receipt. Never paste secrets or real conversation exports into logs or public issues.

| Symptom | Likely causes | Diagnostic steps | Fix | Verification |
|---|---|---|---|---|
| Generic/repeated reply to unrelated messages | Scripted demo repository | Check “Demo” versus “Connected development”; inspect `/health` provider | Connect a synthetic backend account; choose Gemini server-side for actual AI | One synthetic message returns a server-recorded turn; mock responses are not a live check |
| Demo after restart | Login not remembered, explicitly disconnected, web session ended | Inspect saved-login controls; distinguish web from Android/iOS | Reconnect and choose Remember for a synthetic DEV- agent account | Force-stop/reopen while backend runs; correct identity/history loads |
| Reconnect error after restart | Server offline, expired token, corrupt store, identity mismatch | Check health and token status locally without printing token | Start server or reconnect correct credential; forget invalid login explicitly if returning to demo | Expected ID and condition match; chat/task operations no longer blocked |
| Backend unreachable | Stopped server or wrong working directory/port | Open `http://127.0.0.1:8000/health` on PC | Run backend launcher from backend directory; resolve port conflict before another server | Health succeeds and shows expected mode/provider |
| Emulator cannot reach PC server | Used phone's localhost or server not running | Compare connection field with platform | Android emulator: `http://10.0.2.2:8000`; PC browser: `http://127.0.0.1:8000` | Authenticated `/api/participants/me` succeeds from client |
| 401 / invalid token | Expired/revoked/rotated credential | Operator checks account using local CLI/DB tools; do not expose token | Rotate only the intended synthetic account, reconnect fresh credential | Same assigned condition and expected ID; no automatic reassignment |
| 403 | Missing current acknowledgment or restricted condition | Check participant onboarding/condition and API error code | Complete demonstration acknowledgment; control intentionally has no AI | Task controls available; restricted AI still denied |
| AI timeout/quota error | Provider quota, unavailable model, network or hourly cap | Health shows configured provider/model; inspect bounded status, not raw SDK exception | Wait for quota or fix server config; inspect unresolved attempt before explicit new send | Stable-ID replay does not make another generation; fresh synthetic request only when deliberately authorized |
| Retry says unresolved | Same server job is pending or failed | `GET /api/ai-requests/{id}` using the owned token | Wait/check status; cancel failed UI message before an intentional new request | No duplicated turn or automatic repeated charge |
| Agent selector disabled | Only one linked login, different server, active request/focus, participant/control build | Check saved accounts, mode, focus and backend ID | In researcher mode link both synthetic DEV- accounts on one server; finish current work | One tap changes actual account and separate history; ordinary assignment remains locked |
| Wrong/missing history | Different account or task context, local demo versus server | Check active ID, task dropdown, server snapshot and pending cache scope | Select correct context/account; refresh; do not merge stores manually | Owned messages match server and original language |
| Task vanished after connection | Demo and backend datasets are deliberately separate | Compare mode and account ID | Disconnect to view demo or create a synthetic backend task explicitly | No unintended upload or cross-account task copy |
| Edit conflicts / stale version | Another edit, stale form or another device | Compare loaded task version with server | Refresh/reopen form and reapply intended changes | Different stale edits remain rejected; exact response-loss replay can return original receipt |
| Legacy refinement says stale | Optional schema fields absent in old stored JSON | Reproduce with a synthetic legacy fixture | Use backend source containing semantic normalization fix; restart it | `test_integration_sync.py` legacy regression passes |
| No reminder | Opt-out, permission denial, quiet hours, cap, cooldown, paused task/day, inexact OS delay | Settings → reminder status; confirm account and future time | Enable deliberately, grant OS permission, choose eligible future time, refresh/reopen | Pending schedule plus separately observed device delivery; one does not imply the other |
| Old reminder after edit | App has not reconciled or OS already displayed it | Check active account, state and native pending/active lists | Reopen/refresh and complete/cancel/reschedule through app | Old pending request removed; test actual device behavior |
| Notification opens wrong/unavailable task | Different logged-in account or deleted task | Inspect scoped payload/account without credentials | Connect intended account or use active task list | No cross-account task or automatic work start |
| Focus time changed after locking screen | Timestamp calculation, system clock changed | Compare deadline, current time and pause state | Resume normally; document clock changes in tests | Remaining time comes from deadline, not number of UI ticks |
| Language button missing | Old installed APK | Compare current receipt/build with installed app | Full rebuild and `adb install -r`, not only hot reload | Globe and Settings language choice visible |
| Some text remains English in Japanese | User task/history preserved or unknown external error | Identify whether UI label or stored content | Translate missing catalogue label; do not silently rewrite user content | Material/UI localized; original task/chat text unchanged |
| APK build says missing dependency offline | New dependency not in Gradle cache | Read exact Gradle failure | Run `tool/build-android-verified.ps1 -Online` once, then cached build | Successful receipt with matching packaged kernel/source hash |
| Flutter child exits with Windows handle error | Host captured-child process issue | Use documented wrapper and actual log | Verified assemble-then-package helper; never suppress compiler failures | Source and kernel hash verified, successful APK build |
| Android emulator offline | Not booted, acceleration/graphics issue, stale process | `adb devices`, emulator logs and existing AVD config | Launch configured emulator, wait for boot; do not wipe data as a first repair | Device is `device`, boot completed, activity launch Status ok |

## Physical-device notification checks still required

With a **synthetic** account only: opt out first; verify no scheduling. Enable and deny permission; verify clear status and no false delivery claim. Grant permission; schedule a near-future reminder and observe it foreground/background/terminated. Repeat with quiet hours and timezone change, then complete/edit/delete the task and confirm stale reminders are removed. Tap the reminder under the correct and a different account. Test pause-today, daily cap and cooldown. Record exact device/OS/time/account/category. Do not classify an unobserved reminder as “ignored.”

For iOS also test authorization changes, banner presentation, app kill/relaunch, Keychain restoration and provisioning entitlements on macOS/Xcode. None is established by Windows compilation or mocked tests.
